# 3分デモ動画 台本 初版

作成：2026-09-27 杉浦（案）
根拠：企画書のデモストーリー（09:00→09:15→11:32→14:30→18:00）と MVP 3体験＋自己修復。
前提：画面はまだ無い。
「画面」欄は企画書の記述からの [推測]。
ナレーションは実装後の収録用の案で、「置きました」等の完了形は実装を確認してから確定する。
動くものが出た時点で差し替える。
尺：合計 180 秒。
公式要件は「プロジェクトの動作を説明する3分程度のデモ動画」「自作の上、YouTube に公開」。
審査の見せ方：審査員はテストアカウントとサンプルデータで触る（公式）。
動画では「録画した1日分を再生するモード」で判定と通知が起きる様を見せる。
[9/20 の杉浦の提案／実装可否は島村さんの判断]

## ナレーションの原則

- 1カット1メッセージ。
- 「診断しない」「人に戻す」「昨日までと比べる」「自分で気づく」の4つは必ず口に出す。
  審査軸②の語彙に対応させる。
- 数字は原則として口に出さない。
  尺が足りないので画面に出す。
- 例外は「15分後」の1つで、仕組みの説明に要る。
- 競合の名前は出さない。

## 収録の段取り（担当者向けメモ／すべて案）

- 音声は TTS で代替できる。
  企画書が TTS を使うので、ナレーションも同じ声で統一できる。
- 字幕は付けない。
  付けるなら各カットの見出しだけ。
- 撮影は「録画した1日分を再生するモード」があれば1テイクで済む。
  無ければカットごとに撮って繋ぐ。

★ 自己修復（#5）に 35 秒使うか。
推奨：使う。
理由：確認した競合の公開情報に稼働監視の記載が無く、審査軸②の可観測性と③の運用性に当たる。

★ 絵本・将来連携に触れるか。
推奨：触れない。
理由：180 秒に入らない。
記事の第10章で触れる。

★ #3 で「再確認」をデイサービスの予定と絡めて見せるか。
推奨：見せる。
理由：確認した Care-Call.AI のトップと料金ページには、予定連携と同日中の計画的な再確認の記載が無い。
無応答時の自動リダイヤルは記載されている。

★ YouTube の公開範囲。
推奨：限定公開（URL を知っている人のみ）で提出し、可否を公式に確認する。
理由：公式は「YouTube に公開し、URLをプロジェクトにご登録ください」とだけ書いていて、限定公開の可否は明記が無い。
提出締切後にプロジェクトページが一般公開される旨の記載はある。
