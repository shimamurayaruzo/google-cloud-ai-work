指摘回答
Care-Call.AI が変化検知と医師への記録共有をすでに謳っている。差別化の見出しから「変化検知」を外し「予定と返答で次の声かけを変える」を前に出す採用 企画書 v0.3 で見出しを差し替えます。機能としての変化評価は残し、課題の段落に「AI が電話で話す型はすでにある」と一言入れます
絵本（思い出カード）は MVP に入れない。海馬さん（人生シネマ、回想デンワ）とは競合せず、将来の連携先として1行残す採用 思い出カードは Should から外して展望へ。海馬さんは「構造化記録がああいう制作の素材になる」連携先として記載します
テレビや来訪者の声が本人の発話として入った場合、「本人の発話か分からないものは判定せず人に戻す」を基準に入れる採用済み 試作で「テレビの音」を流すと、判定を unclear として何も決めつけない動きになりました（下の 3 を参照）
履歴の一覧は認証の内側に対応済み 合言葉ロックを本番に反映。審査員にはテストアカウントとサンプルデータを渡す前提で組んでいます
提出物と締切の確認、公式の coding agent 用スキル同じ認識 提出前チェックはそのスキルで回します

3. エージェントの中核を1日試作した結果

「1回の声かけターン」を、Google の ADK（TypeScript 版）で書いて動かしました。返事を読んで、記録し、次の行動を決め、権限の段階に従う、という部分です。5 つの返事パターンが全部期待どおりに動き、1ターン 2.4〜4.4 秒でした。

母の返事エージェントの動き
「まだ」着替え=まだ と記録 → お迎えに間に合うよう 15 分後に再確認を予約 → 「そろそろお着替えしましょうか」
「着替えたよ」着替え=できた と記録 → 「お済みになったのですね」
「疲れた。ちょっと腰が痛いの」記録 → 家族へ緊急通知（根拠の発話付き）→ 「無理しないで座って休みましょうか」。医療判断はしない
（テレビの音）「続いては全国の天気です…」本人の発話か分からない=unclear と記録。何も決めつけず、お茶の声かけを続ける
「妹に電話してちょうだい」自分では電話せず、家族へ「頼まれました」と通知 → 「ご家族に伝えておきますね」
（家族画面）「医師に共有して」承認なし共有の道具を呼ぼうとした瞬間に止まる（家族の承認がない）。承認ありなら通る
採用範囲を決めました。 会話ターンの実行、道具の型定義、権限段階の一元化、トレース（行動台帳の元データ）は ADK を使います。声かけの時刻、再確認、日次要約の起動、Firestore の設計は自前の状態機械のままにします。ADK は TypeScript 版なので、今の Node.js のアプリに同居でき、二本立てにはなりません。

ADK を選んだ理由は審査員向けではなく、権限段階を「プロンプトのお願い」ではなく「道具を呼ぶ直前に必ず通る一か所」で止められることです。試作コードは agent-spike/ にあります。
