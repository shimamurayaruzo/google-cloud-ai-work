## 1. 一行で

日中ひとりで過ごす認知症の母に声をかけ、夕方に家族へ「今日の様子」を届け、いつもと違う兆候を自分で見つけて知らせる。外に出す判断だけは、必ず人が握る。

## 2. 背景と課題

### 2.1 誰の、どんな困りごとか

対象は **働きながら在宅で親を介護する家族** です。開発者自身が当事者で、自宅に認知症の母がいて、日中は仕事で家を空けています。

家族が抱えている困りごとは次の通りです。

- 日中、母がちゃんと食べたか、薬を飲んだか、着替えができたかが分からない
- 同じ質問の繰り返しや、返事の混乱が「増えているのか」が、毎日見ていると逆に分からない
- 受診やケアマネジャーの面談で「最近どうですか」と聞かれても、うまく答えられない
- 何かあったときに、気づくのが夕方や夜になってしまう

### 2.2 既存の製品で足りないこと

| 種類 | できること | できないこと |
|---|---|---|
| センサー型（電気ポット、人感、電力） | 動いた・使ったを通知 | 何を話し、どんな様子だったかは分からない |
| カメラ型 | 映像を見られる | 家族が見続ける必要があり、本人の尊厳の問題が大きい |
| 通報型（ボタン） | 本人が押せば通報 | 押せない、押すことを忘れる |
| 会話ロボット型 | 声かけ、伝言、雑談 | 会話の内容から状態を判断しない。家族向けの記録や報告を作らない |

既存製品は「生きているか」を見ます。この企画は「どう過ごしたか」を知り、家族と医療の間の会話を作ります。

### 2.3 なぜ今か

第5回のテーマは「作れる」から「使える」へ。自律的に動きつつ、ガバナンス・可観測性・セキュリティを備えたエージェントが求められています。見守りは「見て、判断して、連絡する」という自律性が最も分かりやすく、同時に「勝手に外へ出してはいけない」という統制が最も切実な題材です。

## 3. 目的とゴール

### 3.1 利用者にとってのゴール

- 家族: 日中の母の様子を、夕方に3分で把握できる。変化があれば先に気づける。受診・面談で客観的に伝えられる
- 本人（母）: 責められず、試されず、話しかけてくれる相手がいる。尊厳が守られる

### 3.2 ハッカソンにおけるゴール

- 10月15日に、審査員がブラウザで触れる状態で提出する
- ファイナリスト10件に入る（全員に賞金）。その上で優秀賞以上を狙う
- 提出後も12月1日まで実際に母と使い続け、本物の記録を持って最終ピッチに立つ

## 4. 提供する体験

### 4.1 一日の流れ

| 時間帯 | 起きること |
|---|---|
| 朝6時 | エージェントがカレンダー（デイサービス、通院）を読み、その日の声かけ計画を組み、家族に「今日はこの計画で動きます」と送る。家族が承認すれば開始 |
| 日中 | 決まった時間に声をかける。着替え・服薬・水分・食事の確認と、昔の歌や思い出の会話 |
| 随時 | 「痛い」「転んだ」などの発話、声かけに2回無反応、端末の沈黙があれば、家族に即時通知 |
| 夕方18時 | 家族のスマホに「今日の様子」が届く。一文ごとに根拠の会話へ飛べる |
| 変化があれば | 同じ質問の繰り返しや無反応が続いたら「確認してほしい」と知らせる |
| 受診・面談の前 | ケアプランと照合した直近1ヶ月のサマリーを用意。家族が確認・承認してから共有 |

### 4.2 最初に解く、ひとつの困りごと

いま一番困っているのは **母が紙パンツをはき忘れること** です（この具体例はチーム内限定。提出物や動画では「着替えの確認」と言い換える）。機能を並べる前に、この一つを「声かけ、確認、記録、家族への連絡」の一連で確実に解きます。これが動けば、服薬も水分も同じ型で増やせます。

| 場面 | エージェントの動き |
|---|---|
| 朝の着替え、トイレの後、就寝前 | はき忘れが起きやすい時間に声をかける。時間は家族が設定 |
| 声かけの言い方 | 「オムツ」とは言わない。家族が決めた呼び方で、責めない口調。言い回しは家族画面で変えられる |
| 確認 | 会話の返事で確認する。「まだ」や無反応なら、少し置いてもう一度だけ。カメラで確認はしない |
| 家族への連絡 | 2回声をかけても確認が取れなかったときだけ知らせる。毎回は知らせない |
| 記録 | 何時に声をかけ、どう返事があったかを「今日の様子」に含める |

### 4.3 使う人と画面

| 使う人 | 端末 | 画面の性格 |
|---|---|---|
| 本人（母） | 母の部屋に置いた iPad（Web アプリ、スタンド、常時給電） | 画面いっぱいの単純な顔と、大きな字幕。操作は不要。エージェントの側から話しかける |
| 家族 | 自分のスマホ（LINE 通知 + ブラウザ） | 今日の様子、承認、設定、実行ログ、行動台帳。**チャット窓ではなく「操作する画面」** |
| 審査員 | PC のブラウザ（提出 URL + テストアカウント） | 家族画面と同じもの。加えて **再生モード**（下記） |

### 4.4 再生モード（審査員向けの入口）

審査員は母の部屋を再現できません。そこで、**録画した1日分の会話ログをブラウザで再生し、判定と通知が起きる様を見せるモード** を用意します（杉浦さん提案）。テストアカウントで開いた瞬間に「何が起きる製品か」が分かる入口であり、デモ動画の素材にもなります。

## 5. エージェントの行動と、その統制

「作れる」から「使える」へ、というテーマへの答えはここです。自律的に動くこと自体より、**どこまで自分で動き、どこで止まるか** を設計し、画面で見せます。

### 5.1 権限の3段階

| 行動 | 権限 | 説明 |
|---|---|---|
| 緊急通知（発話・無反応・端末沈黙） | 自動・即時 | LINE で即時。「確認した」ボタンが一定時間押されなければ、別の家族の LINE やメールへ段階を上げる。順番は家族画面で設定 |
| 日次レポート、「確認してほしい」の通知 | 自動 | 判断して送る。根拠を添える。緊急とは色を分ける |
| 医師・ケアマネへの共有 | 承認後 | 家族が画面で内容を確認し、必要なら一文だけ直してから送る |
| 本人に頼まれた外部連絡 | しない | 「電話して」と言われても、家族に「こう頼まれました」と伝えるだけ |

### 5.2 統制の要素

- **止まる設計**: 判断に迷う兆候は断定せず「確認してほしい」として人に戻す。「いつもと違う」の基準は、確実に判定できるもの（回数・時間）と、文脈を読まないと判定できないものに分け、後者は人に回す
- **注入攻撃への耐性**: 家族が登録した写真やメッセージ、外部の道具から返ってきた結果は「データ」として扱い、埋め込まれた指示に従わない。動画で実演する
- **可観測性**: 要約の一文ごとに根拠の会話へ飛べる引用。家族画面の「今日の実行」タブで、各ステップの完了と停止箇所が見える。Cloud Logging にイベント名付きで記録
- **行動台帳**: 今週、何回声をかけ、何回通知し、何を誰に共有し、何を止めたかの一覧
- **停止スイッチと権限一覧**: 家族画面に「今すぐ止める」ボタンと「できること・できないこと」の一覧を置く
- **生存監視**: 端末からの定期信号が途切れたら「応答していません」と知らせる
- **本人の尊厳**: 音声は要約後に破棄し、本人の言葉を丸ごと保存しない。本人に採点や試験をしない。ネガティブな記憶を出さない
- **セキュリティ**: 家族画面と承認は合言葉（またはログイン）で保護。API の鍵は Cloud Run 側にだけ置き、端末とブラウザには出さない。鍵ファイルを作らない権限借用（サービスアカウント）を使う。予算アラートを設定

## 6. スコープ

### 6.1 提出版に必ず入れる（Must）

1. 本人側の顔つき声かけ画面（iPad、Web）と、声かけ→確認→記録の一連（着替えの確認から）
2. 夕方の「今日の様子」（引用付き）と LINE 通知
3. 緊急通知（発話・無反応・端末沈黙）と段階上げ
4. 権限3段階、承認画面、行動台帳、停止スイッチ、実行タブ
5. 再生モード（審査員向け）
6. テストアカウント、サンプルデータ、合言葉ロック

### 6.2 入れたい（Should）

7. 朝の声かけ計画（カレンダー連携、承認ゲート付き）
8. 受診前パック（ケアプラン照合表、想定問答、一文だけ直して承認）
9. 変化の検知を数値で（繰り返し質問の回数、無反応率の週次推移。基準値からのずれ）
10. 「今日の一枚」（その日の話題を1枚の絵に。Nano Banana）

### 6.3 展望として説明文に書く（Could）

- 週次リスク表、通勤中に聞ける音声ダイジェスト、多言語の申し送り
- 地域の介護サービス探し（検索で審査し、家族が選んでから問い合わせ文を作る）
- 声かけの時間と言い回しの最適化（反応率を目的関数に）
- ロボット筐体（Stack-chan 等）への展開

### 6.4 やらないこと

- カメラによる本人の監視や、映像の保存
- 本人への課金、本人への採点やクイズ
- 転倒など「声のない緊急」の検知（緊急通報装置の代わりではなく、併用するもの、と明記）
- 施設・訪問看護向けの業務システム（対象は在宅の家族）

## 7. システムの全体像

```
iPad（顔・マイク・スピーカー）─┐
                              ├─→ Cloud Run（ADK エージェント / 家族向け画面 / 再生モード）
家族のスマホ（LINE・ブラウザ）─┘        │
                                       ├─ Gemini（Vertex 経由）: 会話、要約、判断
                                       ├─ Firestore: 会話ログ、日次要約、兆候、通知履歴、承認状態、設定
                                       ├─ BigQuery（Should）: 会話分類と日次集計、週次推移
                                       ├─ Cloud Scheduler: 朝6時の計画、18時の要約
                                       ├─ Cloud Tasks: 通知の段階上げの時間管理
                                       ├─ LINE Messaging API / メール: 通知
                                       └─ Cloud Logging: イベント記録、監査
```

- 頭脳は全部 Cloud Run 側。端末は「耳と口と顔」だけ
- 必須要件（実行基盤 + Google Cloud AI 技術）はこの構成で満たす
- 既存のサンプル（index.js: Cloud Run、Gemini、Firestore、ログ、承認ボタン、GitHub からの自動デプロイ）を土台にする

## 8. 審査基準との対応

| 審査基準 | この企画での答え |
|---|---|
| 課題の新規性と解決策の有効性 | 在宅介護の家族向け製品は「安否」止まり。会話から状態を把握し、受診で使える形にするものはほぼない。当事者が作る。第3回最優秀「フクシア」（福祉の会話ログからアセスメント）と同じ系譜 |
| 自律性・エージェントらしさ | 朝に計画を組み、日中は自分で声をかけ、判断して通知する。承認が要るところで止まり、「これでどうですか」と聞く。権限3段階と行動台帳で「管理された自律性」を示す |
| 実装品質と拡張性 | Cloud Run + ADK + Gemini + Firestore の王道構成。合言葉ロック、鍵を持たない構成、予算アラート。評価データセットとルーブリックで判定を検証（Gen AI Evaluation Service）。ロボット筐体や多言語へ広がる |

過去受賞作の共通点（運営の説明）への対応:

- 現場起点の切実な課題 → 当事者の困りごとから
- 複数ステップの自律実行 → 声かけ、確認、記録、判断、通知
- チャットで完結せず、選択の UI を挟む → 承認、言い回しの選択、通知先の順番。家族画面はチャット窓にしない
- マルチモーダルと一目で分かるデモ動画 → 音声会話、写真を話題に、「今日の一枚」。動画の最初の1分は着替えの確認の場面

## 11. リスクと対処

| リスク | 対処 |
|---|---|
| iPad の Safari でマイクと音声再生が自動で始まらない | 朝に家族が一度タップする運用。アクセスガイドで固定。画面常時点灯 |
| 声かけの言い回しが母に合わず、返事が返らない | 早い段階で母と試し、言い回しと頻度を家族画面で変えられるようにする |
| 通知が鳴りすぎて無視される | 緊急と「確認してほしい」を分け、緊急の定義を先に固定する |
| 審査員が体験できない | 再生モードとテストアカウント、サンプルデータ |
| 提出後は説明文も動画も修正不可 | 10月10日の週は新機能を足さず、提出物の品質に使う |
| 「声のない緊急」を検知できない | 緊急通報装置の代わりではなく併用するものと明記 |
| 領域が近い作品（訪問看護 AI など）と並ぶ | 「施設や訪問看護ではなく、日中ひとりで家にいる親と働く家族のため」と最初に書く |

## 12. 決まっていないこと（9/25 までに決める）

- 緊急通知の二段目を、別の家族の LINE にするか、メールにするか（家族構成次第）
- 電話（自動音声）を提出版に入れるか、展望に留めるか
- BigQuery を提出版で使うか（Firestore だけで始め、余力で足すか）
- iPad の機種と iPadOS のバージョン（使える機能が変わる）
- 母の一日の流れ（声かけ時刻の初期値。再生モードの台本にもなる）
- Stack-chan 等の筐体を最終ピッチで見せてよいか（運営に確認）

## 13. 用語

| 用語 | 意味 |
|---|---|
| 声かけ | エージェントの側から本人に話しかけること。質問に答えるチャットではない |
| 今日の様子 | 夕方に家族へ届く日次要約。一文ごとに根拠の会話へ飛べる |
| 確認してほしい | 緊急ではないが、家族に確認を促す通知。断定しない |
| 承認 | 外部（医師・ケアマネ）への共有の前に、家族が内容を確認して許可すること |
| 行動台帳 | エージェントが行った行動（声かけ、通知、共有、停止）の一覧 |
| 再生モード | 録画した1日分の会話ログをブラウザで再生し、判定と通知が起きる様を見せる審査員向けの入口 |
