# 見張らない見守り — 会話から「いつもと違う」に気づく在宅介護エージェント（企画書 v0.2）

第5回 Agentic AI Hackathon with Google Cloud 提出プロジェクト
版: 0.2（2026-09-26 改訂）／ 作成: 島村 ／ 状態: 競合調査と現場ヒアリングを反映した確定版たたき台

v0.1（2026-09-22）からの変更点は末尾の「改訂履歴」にまとめた。

---

## 1. 一行で

日中ひとりで過ごす認知症の母に iPad からやさしく声をかけ、返事と予定から**次の行動を自分で決め**、夕方に家族へ「今日の様子」と「昨日までとの変化」を届ける。カメラでは見張らず、外へ出す判断は家族が握る。穏やかな時間には昔の話を聞いて「思い出カード」に残す。

## 2. 競合調査で分かったこと（2026-09-26）

出典: docs 配下の競合徹底調査（各社公式サイト・公式開発者情報）と、Notion「見守りアプリライブラリ」5件（公式プレスリリース起点）。

「AIが高齢者と話す」「会話を蓄積する」「家族へレポートする」は、すでに市場にある。

| 競合 | 提供しているもの | こちらとの重なり |
|---|---|---|
| Care-Call.AI（月3,980円〜） | AIが電話で定期ヒアリングし、会話を蓄積して家族へレポート | 非常に高い。「会話→記録→家族レポート」だけでは差が出ない |
| BOCCO emo（月1,700〜2,970円） | 会話、会話内容の記憶、家族への音声メッセージ、リマインダー、センサー連携 | 非常に高い。会話ロボットではなく、記憶とセンサーまで持つ |
| Google Home + Gemini（月1,000〜2,000円） | 自然な会話、予定、家電操作、一日の概要 | 会話の質では勝てない。介護固有の目標と承認境界は持たない |
| らいみー、SoftBank みまもり、テラシテ など | 応答確認、スマホ利用、電力から安否推定 | 安否まで。様子の中身は扱わない |
| Ring、Tapo、Panasonic などカメラ | 映像で直接確認 | 思想が違う。本人とヘルパーの監視感が課題 |
| ヤマト運輸 ハローライト訪問プラン（月1,078円） | IoT電球の点灯が24時間ないとメール通知、依頼でスタッフが代理訪問 | 安否まで。人が駆けつける点は AI では代替できない |
| 象印 みまもりほっとライン（月3,300円） | 電気ポットの使用状況を通知、直近1年の2日をグラフ比較 | 「変化を比べる」の先行例。ただし比べるのは操作の有無だけ |
| セコム みまもりホン2 | ストラップで救急通報、端末の自動再起動と電池切れ通知 | 「機械が止まったら知らせる」の先行例。会話や様子は扱わない |

**空いている場所**は「会話の後」にある。会話を記録で終わらせず、①予定と返事から次の行動を自律的に変える、②カメラを使わず複数の生活シグナルで判断する、③本人の楽しみと人生記録を成果物として残す、④エージェント自身の運用品質（可観測性・承認境界・自己復旧）を見せる。この4つを一つのエージェントでつなぐ製品はまだ無い。

## 3. 現場ヒアリングで分かったこと

デイサービスの担当者に、介護と見守り機器について話を聞いた。

- カメラには確かな安心感がある一方、本人が嫌がる場合があり、訪問するヘルパーも「監視されている」と感じることがある
- 介護現場では安全確認のためにカメラ導入が進んでいるので、「カメラは悪」と単純化はしない。**何を知るために、どこまで取得するか**を設計する
- 本人が一人で外出することはなく、外出時は家族が付き添う。GPS は今回の主役にならない
- 支援したい時間は、**家族が仕事や用事でそばにいられない在宅時間**

方針: 提出版では常時カメラを使わない。会話・予定・無反応・非映像センサーでどこまで見守れるかを主軸にする。転倒など音声で拾えない安全課題は、同意を前提にした限定的な映像利用を将来の検討事項として明記する。

## 4. 誰の、どんな困りごとか

対象は **働きながら自宅で認知症の親を介護する家族**。開発者自身が当事者で、自宅に認知症の母がいて、日中は仕事で家を空けている。

- 日中、母がちゃんと食べたか、薬を飲んだか、着替えができたかが分からない
- 同じ質問の繰り返しや返事の混乱が「増えているのか」が、毎日見ていると逆に分からない
- 受診やケアマネジャーの面談で「最近どうですか」と聞かれても、うまく答えられない
- 見守りの機械が止まっていても、家族は気づかない

## 5. 提供する体験

### 5.1 エージェントの内側ループ（一つの確認を合格まで詰める）

単純な時刻通知ではなく、「目標 → 声かけ → 返事と状況の評価 → 次の行動を決める」を回す。返事、無反応、予定、直近の履歴によって、再声かけ・待機・家族通知・緊急扱いを変える。

例: 9:00「今日はデイサービスの日です。お着替えできましたか？」→「まだ」→ 10:00 に迎えが来るので 15 分後に再確認 → 9:15「そろそろお着替えどう？」→「着替えたよ」→ 準備済みとして記録。家族には「準備完了」とだけ届く。

### 5.2 一日の外側ループ

| 時点 | エージェントの仕事 | 判断材料 | 人の関与 |
|---|---|---|---|
| 朝 | 家族が登録した予定を読み、その日の声かけの時刻と内容を決める | デイサービス、通院、前日までの記録 | 家族が LINE で確認・承認 |
| 日中 | 声かけ → 評価 → 次の行動 | 返事、無反応、予定、直近の履歴、非映像センサー | 通常は不要 |
| 異常時 | 「痛い」「転んだ」、連続無反応、端末の沈黙を検知 | 発話と検証ルール | 家族へ即時通知（根拠付き） |
| 穏やかな時間 | 思い出モードへ切り替え、昔の話を一つ聞く | 本人の状態（体調不良や混乱のときは行わない） | 不要 |
| 夕方 | 一日を要約し、昨日までとの変化と根拠を添える | 当日の構造化記録 | 家族へ自動送信 |
| 外部共有 | 医師・ケアマネ向けの要約 | 家族が選んだ期間と項目 | **必ず家族承認** |

### 5.3 「昨日まで」を覚える

会話全文を長期保存せず、食事・着替え・水分・気分・痛み・質問の繰り返しなどを構造化して記録する。日次の状態と短い根拠を蓄積し、「今日はどうか」だけでなく「最近どう変わったか」を評価する。例:「今週、食事について同じ質問を短時間で繰り返す回数が増えています。断定はせず、家族に確認を促します。」

### 5.4 思い出モード（見守りだけで終わらせない）

安全確認と生活タスクだけでは、本人にとって「管理される AI」になる。日中の穏やかな時間には昔の話を聞き、本人の語りを短く整理して、情景のイラストを添えた「思い出カード」にする。家族が後から補足・修正でき、PDF にして印刷できる。

事実と生成は混ぜない。本人が話した内容、家族が補足した内容、AI が描いたイメージを分けて保存し、表示でも区別する。AI は本人の人生の作者ではなく、語りを引き出して整理する編集者として振る舞う。

### 5.5 使う人と画面

| 使う人 | 端末 | 画面の性格 |
|---|---|---|
| 本人（母） | 母の部屋の iPad（Web アプリ、スタンド、常時給電） | 単純で大きな顔と字幕。操作は不要。エージェントの側から話しかける |
| 家族 | 自分のスマホ（LINE 通知 + ブラウザ） | 今日の様子、承認、設定、実行タブ、行動台帳、思い出カード。**チャット窓ではなく操作する画面** |
| 審査員 | PC のブラウザ（提出 URL + テストアカウント） | 家族画面と同じもの。加えて再生モード（録画した1日分の会話ログを再生し、判定と通知が起きる様を見せる） |

複数端末は「外出追跡」ではなく「家の中の役割分担」に使う。iPad への呼びかけに返事がなくても、別室の人感センサーが反応していれば「無反応＝異常」とは扱わない。

## 6. エージェントの行動と、その統制

### 6.1 権限の段階

| レベル | 例 | 扱い |
|---|---|---|
| 自動 | 通常の声かけ、日次要約、家族への注意通知、思い出カードの下書き | エージェントが実行 |
| 自動 + 根拠 | 「痛い」「転んだ」、連続無反応、端末の沈黙 | 即時通知し、根拠となった発話・状態を添える。「確認した」ボタンが一定時間押されなければ別の家族へ段階を上げる |
| 承認後 | 医師・ケアマネへの共有、設定変更、思い出カードの確定 | 家族が確認してから実行 |
| しない | 医療診断、本人に頼まれた任意の外部発信 | 家族へ「頼まれた」と伝えるだけ |

### 6.2 統制の要素

- **止まる設計**: 判断に迷う兆候は断定せず「確認してほしい」として人に戻す。確実に判定できるもの（回数・時間）はコードで決定的に扱い、文脈が要るものだけ Gemini に任せ、どちらの判定かをログに残す
- **注入攻撃への耐性**: 家族が登録した文章や外部の道具の結果は「データ」として扱い、埋め込まれた指示に従わない。動画で実演する
- **可観測性**: 要約の一文ごとに根拠の会話へ飛べる引用。家族画面の「今日の実行」タブ。行動台帳（何回声をかけ、何回通知し、何を誰に共有し、何を止めたか）。Cloud Logging にイベント名付きで記録
- **停止スイッチと権限一覧**: 家族画面に「今すぐ止める」ボタンと「できること・できないこと」の一覧
- **自己復旧（運用エージェント）**: 見守りサービスは「止まっていたことに家族が気づかない」が最も困る。本体とは別に運用エージェントを置き、ログ・エラー・ヘルスチェックを監視する。軽微な障害（音声合成のタイムアウト等）は再試行と代替処理で自動復旧し、Slack に報告する。コード変更が必要な修復は、修正案とテスト結果を提示して人が承認してから反映する（提出版では自動復旧と報告まで。コード修正の承認フローは展望）
- **本人の尊厳**: 音声は要約後に破棄し、本人の言葉を丸ごと保存しない。本人に採点や試験をしない。ネガティブな記憶を出さない。カメラを常時使わない
- **セキュリティ**: 家族画面と承認は合言葉（またはログイン）で保護。鍵は Cloud Run 側にだけ置き、鍵ファイルを作らない。予算アラートを設定

## 7. スコープ（残り 19 日で作るもの）

### 7.1 提出版に必ず入れる（Must）

1. 内側ループ: 朝の着替え確認（予定を読み、未完了なら時間を置いて再確認、それでも取れなければ家族へ）
2. 異常発話と連続無反応の検知 → 根拠付きで LINE 通知 → 未確認なら段階上げ
3. 夕方の「今日の様子」（引用付き）と「昨日までとの変化」（直近 3 日との比較）
4. 権限段階、承認画面、行動台帳、停止スイッチ、実行タブ
5. 再生モード（審査員向け）、テストアカウント、サンプルデータ、合言葉ロック
6. 自己復旧の最小形: ヘルスチェック → 音声合成のタイムアウトを検知 → 再試行と代替処理 → Slack へ報告

### 7.2 差別化として入れる（Should、優先順）

7. 思い出モード 1 テーマ: 本人の語りだけを材料に短い文章と 1 枚のイラスト（Nano Banana）→ 思い出カード → 家族が補足 → PDF
8. 非映像センサー 1 種類: SwitchBot 人感センサー（OpenAPI と Webhook）を接続し、「iPad 無反応だが別室で活動あり」を異常と扱わない判断に使う
9. 変化の検知を数値で（繰り返し質問の回数、無反応率の週次推移。基準値からのずれ）

### 7.3 展望として説明文に書く（Could）

- 運用エージェントによるコード修正ブランチの生成 → 別の評価役でテスト → Slack 承認 → 反映
- 別室スピーカーへの声かけ切り替え、スマート家電イベント（冷蔵庫・炊飯器）の統合
- 受診前パック（ケアプラン照合表、想定問答）、週次リスク表、音声ダイジェスト、多言語の申し送り
- 思い出カードの蓄積 → アルバム・小冊子、声かけの時間と言い回しの最適化
- ロボット筐体（Stack-chan 等）への展開、同意を前提にした限定的な映像利用

### 7.4 やらないこと

- 常時カメラ監視、映像の保存、GPS による外出追跡
- 本人への課金、本人への採点やクイズ
- 医療診断。転倒など「声のない緊急」の検知（緊急通報装置の代わりではなく併用）
- 施設・訪問看護向けの業務システム（対象は在宅の家族）
- Google Home や Alexa の音声 UI そのものの置き換え（会話端末は iPad の Web アプリ。将来の連携先として扱う）

## 8. システムの全体像

```
iPad（顔・マイク・スピーカー）──┐
SwitchBot 人感センサー（Webhook）─┤
家族のスマホ（LINE・ブラウザ）──┴─→ Cloud Run
                                     ├─ 見守りエージェント（ADK）: 計画 → 声かけ → 評価 → 次の行動
                                     ├─ 運用エージェント: ヘルスチェック、再試行、代替処理、Slack 報告
                                     ├─ 家族向け画面 / 再生モード
                                     ├─ Gemini（Vertex 経由）: 会話、要約、判断、思い出の整理
                                     ├─ Nano Banana: 思い出カードのイラスト
                                     ├─ Firestore: 構造化記録、日次状態、通知履歴、承認状態、思い出カード
                                     ├─ Cloud Scheduler / Cloud Tasks: 朝の計画、18時の要約、通知の段階上げ
                                     ├─ LINE Messaging API / メール / Slack: 通知
                                     └─ Cloud Logging: イベント記録、監査
```

## 9. 審査基準との対応

| 審査基準 | この企画での答え |
|---|---|
| 課題の新規性と解決策の有効性 | 「会話→記録→レポート」は Care-Call.AI や BOCCO emo にある。差は会話の後にある。予定と返事から次の行動を自律的に変え、カメラを使わず複数シグナルで判断し、本人の人生記録まで成果物にする。当事者が作り、現場ヒアリングで方針を修正した |
| 自律性・エージェントらしさ | 内側ループ（目標→声かけ→評価→決定）と外側ループ（朝→日中→夕方）。承認境界で止まり、「これでどうですか」と聞く。本人の状態を見て、見守りと思い出のどちらのモードで動くかを自分で切り替える |
| 実装品質と拡張性 | Cloud Run + ADK + Gemini + Firestore。決定論でできることはコードで。生成と評価を分ける。運用エージェントが自分の障害を監視し復旧する。合言葉ロック、鍵を持たない構成、予算アラート。Gen AI Evaluation Service で判定を検証 |

運営が挙げた過去受賞作の共通点（現場起点の切実な課題／複数ステップの自律実行／チャットで完結せず選択の UI を挟む／マルチモーダルと一目で分かるデモ動画）には、上の設計でそれぞれ答える。マルチモーダルは音声会話、思い出カードのイラスト生成、人感センサーで満たす。

```
09:00  AI「今日はデイサービスの日です。お着替えできましたか？」
09:00  母「まだ」
       → 10:00 に迎え。15 分後に再確認と決める。
09:15  AI「そろそろお着替えどう？」
09:15  母「着替えたよ」
       → 準備済みとして記録。家族には「準備完了」とだけ。

11:32  母「ちょっと腰が痛いの」
       → 医療判断はせず、家族へ根拠付きで通知。「確認した」ボタン。

13:40  iPad の呼びかけに返事なし。別室の人感センサーは反応あり。
       → 異常とは扱わず、少し置いて再確認。

15:00  状態が落ち着いているので思い出モード。
       AI「子どものころ、好きだった食べ物は？」
       母「母が作ってくれたおはぎ」
       → 「母のおはぎ」の思い出カードを下書き。家族が後から補足できる。

16:10  音声合成がタイムアウト
       → 運用エージェントが検知 → 再試行 → 復旧 → Slack へ報告。

18:00  家族へ
       「今日は 9:15 に着替えを確認。11:32 に腰痛の訴えがあり通知済み。
        午後は『母のおはぎ』の話をしてくれました。思い出カードが 1 枚増えています。
        最近 3 日と比べて、質問の繰り返しは増えていません。」
```

注入攻撃の防御（家族が登録した文章に埋め込まれた指示を無視する）は、動画の中で 10 秒の実演として入れる。

## 13. リスクと対処

| リスク | 対処 |
|---|---|
| 19 日で Should まで届かない | Must を 10/8 までに固め、Should は 7 → 8 → 9 の順に入れる。届かなかったものは展望に書く |
| iPad の Safari でマイクと音声再生が自動で始まらない | 朝に家族が一度タップする運用。アクセスガイドで固定 |
| 声かけの言い回しが母に合わない | 早い段階で母と試し、言い回しと頻度を家族画面で変えられるようにする |
| 通知が鳴りすぎて無視される | 緊急と「確認してほしい」を分け、緊急の定義を先に固定する |
| 思い出モードで AI が物語を補完しすぎる | 本人の語り／家族の補足／AI 生成を分けて保存し、表示でも区別する |
| 審査員が体験できない | 再生モードとテストアカウント、サンプルデータ |
| 会話の質で Google Home や Care-Call.AI に見劣りする | 会話の質で競わない。会話の後の自律行動、承認境界、成果物（思い出カード）、運用品質で差を出す |
| 領域が近い作品（訪問看護 AI など）と並ぶ | 「施設や訪問看護ではなく、日中ひとりで家にいる親と働く家族のため」と最初に書く |

## 14. 決まっていないこと

- 緊急通知の二段目を別の家族の LINE にするか、メールにするか（家族構成次第）
- 電話（自動音声）を提出版に入れるか（現状は展望）
- BigQuery を提出版で使うか（Firestore だけで始め、余力で足す）
- iPad の機種と iPadOS のバージョン
- 母の一日の流れ（声かけ時刻の初期値。再生モードの台本にもなる）
- SwitchBot 人感センサーの購入（1 台、数千円）と Wi-Fi 環境
- 運用エージェントの Slack 通知先（チームの Slack か、家族用の別チャンネルか）
- Stack-chan 等の筐体を最終ピッチで見せてよいか（運営に確認）

## 16. 用語

| 用語 | 意味 |
|---|---|
| 声かけ | エージェントの側から本人に話しかけること。質問に答えるチャットではない |
| 内側ループ | 一つの確認を「目標→声かけ→評価→次の行動」で合格まで詰める動き |
| 今日の様子 | 夕方に家族へ届く日次要約。一文ごとに根拠の会話へ飛べる |
| 確認してほしい | 緊急ではないが、家族に確認を促す通知。断定しない |
| 承認 | 外部（医師・ケアマネ）への共有や設定変更の前に、家族が内容を確認して許可すること |
| 行動台帳 | エージェントが行った行動（声かけ、通知、共有、停止）の一覧 |
| 思い出カード | 本人の語りを短く整理し、イラストを添えた 1 枚。本人の語り／家族の補足／AI 生成を分けて持つ |
| 運用エージェント | 見守りエージェント自身の障害を監視し、軽微なものは復旧し、報告する別のエージェント |
| 再生モード | 録画した 1 日分の会話ログをブラウザで再生し、判定と通知が起きる様を見せる審査員向けの入口 |
