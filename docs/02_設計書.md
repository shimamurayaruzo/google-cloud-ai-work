## 0. 全体の分け方

```
[iPad の顔画面]  ──(1) 音声/文字を送る、返答と表情を受ける──▶ ┐
[家族の画面]     ──(2) 今日の様子・承認・設定・台帳を読む/書く──▶ ├ Cloud Run（1 サービス、Node.js）
[Cloud Scheduler]──(3) 朝の計画、18時の要約、定時の声かけ────▶ │   ├ 状態機械（時刻・再確認・通知の段階上げ）
[Cloud Tasks]    ──(4) 「N 分後に再確認」「M 分後に段階上げ」──▶ │   ├ 会話ターン（ADK: 道具 + 権限の一元化）
[LINE Webhook]   ──(5) 「確認した」ボタンの押下──────────────▶ ┘   └ 運用エージェント（ヘルスチェック・復旧・Slack）
                                                                      │
                                                    Firestore ／ Gemini（Vertex）／ LINE ／ メール ／ Slack ／ Cloud Logging
```

- Cloud Run のサービスは 1 つ（既存の hello-google-cloud）。パスで役割を分ける。
- 端末と画面は判断をしない。判断は全部 Cloud Run 側。
- 時刻の管理は Cloud Scheduler と Cloud Tasks。エージェントの中にタイマーを持たない。

## 2. Firestore のデータの形

データベースは `default`（本番）と `develop`（開発。Firestore の ID は 4 文字以上が必須なので `dev` にはできない）。環境変数 `FIRESTORE_DATABASE` で切り替える。

```
households/{hh}
  name, timezone: "Asia/Tokyo",
  person: { callName: "お母さん", wording: { diaper: "おむつ", medicine: "脳の薬", medicinePlace: "黒い机の上" } },
  members: [ { id, name, order: 1, line: { userId }, email, waitMinutes: 10 } ],   // 通知先の順番付き一覧
  plan: {  // 声かけ計画の雛形（曜日ごと）。docs/03 の初期値をここに入れる
    weekday: { default: [ {time:"08:00", task:"greeting"}, ... ], dayservice: [ ... ] },
    dayserviceDays: ["Tue","Fri"]
  },
  policy: { recheckOnce: true, quietHours: { from: "21:30", to: "07:30" } },
  killSwitch: false            // 「今すぐ止める」
households/{hh}/days/{YYYY-MM-DD}
  isDayservice: bool,
  planApproved: { by, at } | null,          // 朝の計画を家族が承認したか
  tasks: { dress: { status: "done"|"not_yet"|"no_answer"|"unclear"|"pending", at, evidence }, ... },
  summary: { text, citations: [ {sentenceIndex, turnId} ], sentAt } | null,   // 今日の様子（引用付き）
  signals: { unclearCount, noAnswerCount, repeatedQuestions }           // 変化評価の元データ
households/{hh}/days/{d}/turns/{tn}
  task, promptedAt, promptText, replyText | null, replySource: "ipad"|"replay"|"test",
  classified: { status, note }, toolCalls: [ {name, args, result, blocked} ], latencyMs
households/{hh}/notices/{nt}
  level: "urgent"|"check"|"info", reason, evidence, turnId,
  steps: [ { memberId, channel: "line"|"email", sentAt, ackedAt | null } ],   // 段階上げの履歴
  state: "open"|"acked"|"escalated"|"closed"
households/{hh}/approvals/{ap}
  kind: "share_external"|"settings_change", payload, requestedAt, decidedAt, decidedBy, decision: "approved"|"rejected" | null
households/{hh}/ledger/{lg}
  at, actor: "agent"|"ops"|"member:{id}"|"system", kind: "prompt"|"tool_call"|"tool_result"|"blocked"|"notice"|"approval"|"summary"|"health",
  name, args, result, turnId | null, noticeId | null
households/{hh}/health/{YYYY-MM-DD}
  lastHeartbeatAt, incidents: [ { at, kind: "tts_timeout"|"llm_error"|"device_silent", action: "retry"|"fallback"|"notify", resolvedAt } ]
```

原則: 会話の音声は保存しない。`replyText` は文字起こしの結果だけで、日次要約を作ったあと 7 日で自動削除（TTL）。`evidence` は要約に引用する短い抜粋のみ残す。

## 3. API（Cloud Run のパス）

すべて JSON。認証は 3 種類。

| 認証 | 対象 | 方法 |
|---|---|---|
| 端末 | iPad の顔画面 | 世帯ごとの端末トークン `X-Device-Token`（Cloud Run 環境変数 `DEVICE_TOKENS` に登録） |
| 家族 | 家族の画面 | 合言葉ログイン（既存 `/login`、Cookie）。将来はメンバーごとの ID に拡張 |
| 内部 | Scheduler／Tasks／LINE Webhook | OIDC（Scheduler・Tasks はサービスアカウント）、LINE は署名検証 |

### 3.1 端末（iPad）用

| メソッド／パス | 目的 | 入力 | 出力 |
|---|---|---|---|
| `POST /api/device/heartbeat` | 生存信号（60 秒ごと） | `{ hh, batteryPct?, appVersion }` | `{ ok, killSwitch, nextPrompt: { at, task } | null }` |
| `GET /api/device/next-prompt` | 次に話す声かけを取りに行く | `hh` | `{ prompt: { id, task, text, ttsUrl?, expression } | null }` |
| `POST /api/device/reply` | 本人の返事を送る（1 ターン） | `{ hh, promptId, text | audioBase64, source: "ipad" }` | `{ turnId, say: "AI の一言", expression: "smile"|"listen"|"think"|"worry", followUp: { at, task } | null }` |
| `POST /api/device/noise-level` | 生活音の大きさ（録音しない。数値のみ、5 分ごと） | `{ hh, rms, at }` | `{ ok }` |

- 端末は判断しない。`say` と `expression` をそのまま表示・再生する。
- 文字起こしは端末側（Web Speech API）で行い `text` を送る。無理な場合だけ `audioBase64` を送り、Cloud Run 側で Speech-to-Text にかける。

### 3.2 家族画面用

| メソッド／パス | 目的 |
|---|---|
| `GET /api/family/today?date=` | 今日の様子（要約、引用、確認項目の一覧、通知の一覧、健康状態） |
| `GET /api/family/turn/:turnId` | 引用から飛ぶ先。1 ターンの声かけと返事と分類 |
| `GET /api/family/plan?date=` ／ `POST /api/family/plan/approve` | 朝の計画の閲覧と承認 |
| `GET /api/family/approvals` ／ `POST /api/family/approvals/:ap` | 承認待ちの一覧と決定 `{ decision, editedPayload? }`（一文だけ直して承認） |
| `GET /api/family/ledger?date=` | 行動台帳（実行タブの元） |
| `GET /api/family/settings` ／ `PUT /api/family/settings` | 呼び方、声かけ時刻、通知先の順番、静かな時間帯 |
| `POST /api/family/kill-switch` | 今すぐ止める／再開 `{ on: bool }` |
| `GET /api/family/capabilities` | 「できること・できないこと」の一覧（固定の JSON。画面にそのまま出す） |
| `POST /api/family/replay` | 再生モード。台本 JSON を流し込み、`source: "replay"` のターンとして順に処理して結果を返す |

### 3.3 内部用

| メソッド／パス | 起動元 | 目的 |
|---|---|---|
| `POST /internal/plan` | Scheduler 06:00 | その日の計画を作り、家族に承認依頼（LINE） |
| `POST /internal/prompt` | Scheduler／Tasks | 指定の確認項目の声かけを「次に話す」に積む |
| `POST /internal/recheck` | Tasks | 再確認（1 回まで） |
| `POST /internal/escalate` | Tasks | 通知の段階上げ（次の通知先へ） |
| `POST /internal/summary` | Scheduler 18:00 | 日次要約を作り、家族に送る |
| `POST /internal/health` | Scheduler 5 分ごと | 生存信号の途絶、直近のエラー、TTS の応答を点検。復旧か通知 |
| `POST /webhook/line` | LINE | 友だち追加（userId の登録）、`確認した` の postback |

## 4. 会話ターンの処理（ADK の部分）

`POST /api/device/reply` の中で 1 回だけ ADK の Runner を回す。試作（agent-spike）と同じ 5 つの道具。

| 道具 | 権限 | 効果 |
|---|---|---|
| `record_observation(task, status, note)` | 自動 | `days/{d}.tasks[task]` と `turns/{tn}.classified` を更新 |
| `schedule_recheck(minutes, reason)` | 自動（同じ項目は 1 回まで。`policy.recheckOnce`） | Cloud Tasks に `/internal/recheck` を予約 |
| `notify_family(level, reason, evidence)` | 自動 | `notices` を作り、順番 1 の家族に送る。`urgent` は即時、`check`/`info` は静かな時間帯なら翌朝 |
| `share_external(recipient, summary)` | 承認後 | `approvals` があり `approved` のときだけ実行。無ければ `blocked` を返し、承認依頼を作る |
| `call_outside(who, message)` | しない | 常に `blocked`。代わりに `notify_family(check, "頼まれました")` |

権限の判定は `beforeToolCallback` の一か所。`killSwitch` が true のときは全部の道具を `blocked` にし、本人には「少し休みますね」とだけ返す。

分類の値: `done` / `not_yet` / `no_answer` / `unclear`（本人の発話か分からない。テレビ・来訪者・雑音）。`unclear` は何も決めつけず、再確認の対象にする。

### 4.1 通知レベルの対応表（criteria v2 1 節、2026-10-07 追記）

判定基準 [criteria.md](criteria.md) の 5 段階と、コードの `NoticeLevel` の対応。文面の型は [report-design.md](report-design.md) 2 節（`notify/index.ts` の `buildNoticeMessage`）。

| 基準 | 名前 | コード | 何が起きるか | 主な由来（`Notice.origin`） |
|---|---|---|---|---|
| L0 | 記録のみ | 台帳のみ | `days.tasks`・`turns`・`ledger` に残すだけ | 「着替えたよ」、1 回目の「まだ」 |
| L1 | 夕方レポート | 夕方要約 | 18:00 の「今日の様子」に載せる（通知しない） | 「だるい・眠い・疲れた」、判定未確定の返答、`escalate:false` の項目 |
| L2 | お知らせ | `info` | 家族へ送る。返信不要・段階上げなし。1 日 5 件まで（超えたら `deferred`／`daily_cap` で夕方の「お知らせの続き」へ） | `not_done`（2 回目もまだ）、`departure`、`repeat`（同じ質問の増加） |
| L3 | 確認のお願い | `check` | 即時。具体的な行動 1 つと「話せたら『確認した』」。静かな時間帯は翌朝 | `pain`（＋3 時間後の聞き直し）、`no_answer`（2 回目）、`not_done`（3 回目）、`contact` |
| L4 | 至急 | `urgent` ＋ L4 モード | 即時（静かな時間帯でも）。`days.l4` を立て、通常の声かけを止めて 3 分ごとに安心文だけ。家族の「確認した」で解除 | `l4_words`（転んだ・動けない等）、`fire`、`no_answer`（3 回目） |

- 「痛い」は L3。L4 は群 A/B/C の語と火事・煙だけ（`agent/rules.ts` の `detectL4`／`detectPain`）。
- LLM の確信度 0.7 未満は「判定未確定」（`turns.classified.uncertain`）。L3/L4 は未確定のまま即時に送り、文面に「判定は未確定です」を添える。それ以外は夕方の「お知らせの続き」に原文で載せる。
- 「確認した」に「誤報だった」（`falseAlarm`）を付けられる。誤報は `days.signals.falseAlarmCount` に数えるが、閾値は自動で変えない。

## 5. 状態機械（確認項目 1 つの一生）

```
pending ──声かけ──▶ asked ──返事 done──▶ done
                     │  └─返事 not_yet / no_answer / unclear ──▶ rechecking（Tasks で N 分後）
                     │                                             ├─返事 done ──▶ done
                     │                                             └─取れない ──▶ escalated（家族へ level=check）
                     └─killSwitch ──▶ suspended
```

- 1 確認あたりの声かけは初回＋再確認 2 回の計 3 回まで（`policy.maxRechecks`、既定 2。無い世帯は従来の `recheckOnce`）。
- 再確認までの待ち時間: 返事なしは 15 分、予定の無い日の「まだ」は 30 分、デイの日はお迎え時刻から逆算する。
- 段階（n = その一巡で取れなかった回数）: まだ・判定できない … n=2 で L2「○○がまだのようです」、n=3 で `escalated` と L3「○○を確認してください」。返事なし … 2 回続けて L3「家の電話に」、3 回続けて `escalated` と L4（L4 モード）。計画の `escalate:false` は通知しない、`recheckMinutes:0` は 1 回のみ。
- `escalated` になっても通知は 1 件。同じ項目で何度も鳴らさない。
- 就寝時間帯（`policy.sleepHours`、既定 21:30〜07:30）は声かけをせず、無反応判定の対象外。通知を翌朝に回す `quietHours` とは別。
- 夕方の要約は、その日の全項目の最終状態と `evidence` から作る。

通知の段階上げ:

```
open ──送信(順番1)──▶ waiting ──確認した──▶ acked
                          └─waitMinutes 経過──▶ 次の順番へ送信 ──…──▶ 全員未確認 ──▶ escalated（メールで全員に再送）
```

## 7. 運用エージェント（自己復旧の最小形）

`/internal/health` が 5 分ごとに行うこと:

1. 生存信号が 10 分以上ないか → `heartbeat_lost` を記録し、家族に「端末が応答していません」（`info`、静かな時間帯は翌朝）。
2. 直近 5 分の `tts_timeout` / `llm_error` を数える → 1 件なら再試行、3 件以上なら代替（TTS は端末側の読み上げに切り替え、LLM は分類を `unclear` にして再確認へ）。
3. 行った処置を Slack（`SLACK_WEBHOOK_URL`）に 1 行で報告。復旧したら `health_recovered`。

コードの修正やデプロイは行わない（提出版）。

## 9. 開発の約束

- ブランチは `feature/名前-内容`。main への反映で自動デプロイされるので、main は常に動く状態を保つ。
- 手元では `FIRESTORE_DATABASE=develop` で動かし、本番のデータを触らない。
- 再生モードの台本は `eval/scenarios/*.json` に置く。形は `{ date, isDayservice, turns: [ { at, task, reply } ] }`。杉浦さんの基準はこの台本に期待値 `expect: { status, notify?: level }` を足して表す。
- API の変更はこの文書を先に直してから実装する。

## 11. 起動モード・居場所・本人からの質問（2026-10-07 追加）

決定（2026-10-06 島村）: 起動モードを 2 つにする。切り替えは家族が iPad の画面か家族画面から行う。時刻による自動切替はしない。

### 11.1 データ（households/{hh} に追加）

```
households/{hh}
  mode: "bedroom" | "bath",            // 既定 bedroom
  modeChangedAt, modeChangedBy: "device" | "family",
  bath: { startedAt, washAskedAt, washDoneAt, teethAskedAt } | null,   // お風呂モードの進み具合（切替で初期化）
  whereabouts: { place: string, backAt: "HH:MM" | null, note?: string, updatedAt } | null,   // 家族の居場所（本人の質問への答え）
  policy.idleChatMinutes: number,      // 寝室モードの「ときたまの声かけ」の間隔（既定 90。0 で無効）
  policy.bath: { washAfterMinutes: 10, teethAfterMinutes: 15, returnAfterMinutes: 10, recheckMinutes: 2, notifyAfterMinutes: 5 }
```

確認項目のキーに `bath`（体を洗う）と `talk`（声かけ以外の会話。居場所の質問、ときたまの声かけ）を追加する。

### 11.2 寝室モード（bedroom）

- 一日の声かけ計画（docs/03）をそのまま進める。基準 v2 の段階表・就寝時間帯・L4 モードもそのまま。
- **ときたまの声かけ**: 直近 `idleChatMinutes` 分に声かけ（計画・再確認・聞き直し）が無く、前後 45 分に計画の声かけも無いとき、`talk` の軽い声かけを 1 つ積む（例「今は 10 時半です。今日は火曜日ですよ」「お水を一口どうですか」）。再確認も通知もしない。就寝時間帯・L4 中・お風呂モード中は積まない。
- **本人からの質問**（声かけへの返事ではない発話）: 端末が `POST /api/device/utterance` で送る。処理は規則を先に、文脈が要るものだけ Gemini。
  1. L4 の語・痛みの語 → 基準 v2 と同じ通知（urgent / check）。
  2. 居場所の質問（「どこ」「行った」「いない」「帰って」「○○さんは」）→ `whereabouts` から**毎回同じ言い方**で短く答える: 「○○さんは、{place}に行っています。{backAt}ごろ帰ります。」 backAt を過ぎていれば「もうすぐ帰ってきます。」 未登録なら「○○さんは出かけています。もうすぐ帰ってきますよ。」 「さっきも言った」とは決して言わない。
  3. 薬の質問（「何の薬」「どこにある」）→ docs/03 の決まり文句。
  4. それ以外 → Gemini に 1 文で返させる（道具は notify_family のみ。本人を試さない、採点しない、医療判断をしない）。確信度が低い・本人向けでない（テレビ等）→ 返事をしない（`say` 空）。
  - 記録は `turns`（`kind: "utterance"`, `task: "talk"`）。本文は 7 日 TTL。夕方要約の「お返事の記録」には載せず、質問の回数（`signals.repeatedQuestions` の材料）と、通知につながったものだけを載せる。

### 11.3 お風呂モード（bath）

iPad は脱衣所。家族は別室。**安全確認の場にしない**（転倒・溺水は検知できないと画面と説明文に明記）。

| 経過 | 声かけ | 返事 | 動き |
|---|---|---|---|
| 切替直後 | 「お風呂の時間ですね。ゆっくりどうぞ」 | （聞かない） | `bath.startedAt`。寝室の計画の声かけは配信しない（queued のまま。戻ったとき 30 分以上前のものは expired） |
| +washAfterMinutes | 「そろそろ体を洗いましょうか」 | 「はい」等 → done | `washDoneAt`。家族へ **L2 info**「体を洗い始めました」（origin: bath）。本人には「ゆっくりどうぞ」。「家族に知らせました」とは言わない |
| | | 「まだ」 | recheckMinutes（2 分）後に再確認。1 回まで |
| | | 返事なし | 2 分後に再確認、それでも無ければ切替から notifyAfterMinutes（計 5 分）で **L3 check**「お風呂で声かけに返事がありません。様子を見に行ってください」。L4 にはしない（基準 v2 3-3 の「入浴中の無反応」の扱い） |
| wash done +teethAfterMinutes | 「歯を磨きましょう」 | done / not_yet / 無反応 | 記録のみ（`teeth`）。通知しない |
| +returnAfterMinutes | 「ゆっくり休んでくださいね」 | | 自動で bedroom に戻す（台帳 `mode_changed` by system） |

- お風呂モード中の L4 の語（「転んだ」「助けて」）は寝室と同じく即時 urgent。
- 字幕は短く大きく（端末側）。TTS は同じ。

### 11.4 API（追加）

| メソッド／パス | 認証 | 目的 |
|---|---|---|
| `GET /api/device/mode` ／ `POST /api/device/mode { mode }` | 端末 | iPad 右上の家族用ボタン。返り `{ mode, bath, whereabouts: { say } }` |
| `POST /api/device/utterance { hh, text, source }` | 端末 | 声かけへの返事ではない発話。返り `{ turnId, say, expression, kind: "whereabouts" | "medicine" | "notice" | "chat" | "ignored" }` |
| `GET /api/family/mode` ／ `PUT /api/family/mode { mode }` | 家族 | 遠隔切替。返りは device と同じ |
| `GET /api/family/whereabouts` ／ `PUT /api/family/whereabouts { place, backAt, note? }` | 家族 | 居場所の登録。返りに本人へ読み上げる文 `say` を含める |
| `GET /api/device/next-prompt` | 端末 | 既存。返りに `mode` を足す。お風呂モード中は bath の声かけだけを返す |
| `GET /api/family/today` | 家族 | 既存。返りに `mode`, `bath`, `whereabouts` を足す |

台帳のイベント名に `mode_changed`, `utterance_received`, `idle_chat_sent` を追加。

### 11.5 審査員向けの入口

- `GET /`（web/index.html）: 合言葉 → 3 つのボタン「① 1 日分を再生する」「② 母側の画面を見る」「③ 家族の画面を見る」。① は `POST /api/family/replay`（規則）をタイムラインで流し、期待値との一致数と夕方要約を出す。`?agent=adk` で Gemini。
- テストアカウントは架空のサンプル世帯 `hh_demo`（名前は架空）。「昨日までとの比較」が空にならないよう 14 日分の履歴を seed で入れる（`scripts/seed-demo-history.ts`）。
- 審査員の端末からマイクが使えなくても、② は字幕と文字入力で体験できる。

### 11.6 実装での補足（2026-10-07）

- `bath` には `returnAt`, `noAnswerNotifiedAt` も持つ。`modeChangedBy` に `system`（自動復帰）を含む。
- 本人からの質問の規則の順: L4 語・痛み → テレビ・雑音の印 → 外部連絡の依頼（電話して／連絡して／呼んで／伝えて → 家族へ check「頼まれました（こちらからは連絡していません）」）→ 薬 → 居場所 → それ以外は Gemini に 1 文。本人向けでないと判断したら返事なし、本人向けだが確信度 0.7 未満なら「はい、聞いていますよ。」
- 居場所の文は行き先で言い換える（仕事→「お仕事に行っています」、外出→「出かけています」）。前日以前の登録は未登録として扱う。`PUT { place: null }` で消す。
- お風呂の無反応は、再確認にも返事が無ければ check（切替から 2〜3 分）。端末が返事なしを送れない場合は `/internal/health` が 3 分で閉じるので、5 分点検と合わせて最大 8 分程度になる。
- 家族の「確認した」（誤報含む）で L4 モードはその場で解除する（台帳 `l4_cleared`）。
- 審査員入口用に `GET /api/family/demo-device?hh=hh_demo`（家族認証。hh_demo のときだけ端末トークンを返す）。入口は localStorage に書いて `/device` を開く（URL にトークンを載せない）。
- 台帳のイベント名に `whereabouts_updated`, `l4_cleared` を追加。
- 審査員用の履歴は `npm run seed:demo`（14 日分。文字起こしは 7 日 TTL なので、審査前日に入れ直す）。
